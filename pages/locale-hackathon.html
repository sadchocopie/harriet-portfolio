01 · The Idea

Catch it in Figma, not in production

Localization QA always gets caught too late. By the time a Canadian French content issue surfaces in a shipped experience — wrong register, false friend, technically-translated-but-completely-off-brand — the fix is expensive. Dev is done. Strings are baked in. Everyone's already moved on.

Sam Kirby and I built Locale to move that review into Figma, before handoff, while fixes are still cheap.

02 · How It Works

Plugin extracts. Agent reviews. Annotations land in your file.

A Figma plugin extracts all text from a selected frame, runs it through DeepL for translation, and writes a duplicate translated frame to canvas — original and translation side by side.

A Claude agent then reads both frames via Figma MCP, QAs the translated content against Quebec French linguistic conventions and Intuit brand voice, and writes annotation notes directly onto flagged layers in the original frame. The audit lives in your file, before a developer has touched a single string.

03 · So What

AI auditing against a real standard — not generating design

The AI here isn't generating design — it's reviewing it against a real standard. That's a more useful and underexplored use case than most "AI in design" conversations get to.

The Figma MCP + agent pattern is portable to any content review: accessibility language, brand voice, tone. We built it for fr-CA because that was the real problem. The pattern is the thing worth keeping.
